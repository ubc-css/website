# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Marketing/landing site for UBC's Cognitive Systems Society (CSS) club. React 19 + TypeScript, built with Vite. Routed with `react-router-dom` (`BrowserRouter`) — currently the homepage (`/`, hero + scroll-revealed folder showcase), an Upcoming Events page (`/events/upcoming`), a Past Events page (`/events/past`), a Merch page (`/merch`), an About page (`/about`), and a placeholder Resources page (`/resources`). New sections *within* a page become new components under `src/components/`; new top-level pages go under `src/pages/<Name>/` and get a `<Route>` in `App.tsx`.

## Commands

```bash
npm run dev       # start Vite dev server with HMR
npm run build     # type-check (tsc -b) then production build via Vite
npm run lint      # eslint .
npm run preview   # preview the production build locally
```

There is no test suite configured in this repo.

## Architecture

- `src/main.tsx` wraps `App` in `<BrowserRouter>` and mounts it into `#root` in `index.html`.
- `src/App.tsx` is just the route table: a `<Route element={<Layout />}>` wrapping `<Route path="/" element={<Home />} />`, `<Route path="/events/upcoming" element={<UpcomingEvents />} />`, `<Route path="/events/past" element={<PastEvents />} />`, `<Route path="/merch" element={<Merch />} />`, `<Route path="/about" element={<About />} />`, and `<Route path="/resources" element={<Resources />} />`. Adding a new page means adding a `src/pages/<Name>/<Name>.tsx` and one more `<Route>` here — no other App.tsx changes needed.
- `src/components/Layout/Layout.tsx` is the persistent shell shared by every route (this is what `App.tsx` used to be, before routing existed): the `site-shell` wrapper (pointer-tracking for a CSS spotlight effect, `Layout.css`) rendering `<Cursor /> <Header /> <Outlet /> <Footer />`. Only the `<Outlet />` content — the current page — changes between routes; Header/Footer/Cursor/the spotlight background are identical on every page. `ScrollCue` is *not* here despite being sitewide-feeling — it scrolls to `#folder-showcase`, which only exists on the homepage, so it lives in `src/pages/Home/Home.tsx` instead.
- `src/pages/Home/Home.tsx` — the homepage's content (`<Hero /> <FolderShowcase /> <ScrollCue />`), rendered inside `Layout`'s `<Outlet />`. Has no CSS of its own; it's pure composition, same as `App.tsx` used to be.
- `src/pages/PastEvents/PastEvents.tsx` + `.css` — search box + a native `<select>` year filter (`'All'` or a specific year — a real `number`, not a display string like `'2025/26'`, so `years` sorts numerically via `.sort((a, b) => b - a)` rather than relying on string sort; `src/components/PastEventCard/formatAcademicYear.ts` derives the `'2025/26'`-style label for display) combined with the search text via AND, over an array of past events, each rendered as an `src/components/PastEventCard/EventCard.tsx` (component folder is `PastEventCard`; the file/component name inside stayed `EventCard`).
- `src/components/PastEventCard/EventCard.tsx` + `.css` — one past event: name/description on the left, a small hand-rolled photo carousel (prev/next buttons with wraparound, clickable dot indicators, no library) on the right, stacking on mobile. Deliberately reuses `FolderPreview.css`'s `.folder` visual language (same asymmetric `border-radius: 6px 26px 26px 26px`, gradient background, colored tab cycling through the same 4 palette accents) so it reads as "the same kind of folder" as the homepage — but as a plain static two-column card, not `FolderPreview`'s absolutely-positioned scatter/hover system, since this page is for browsing rather than a playful reveal. Fades in on scroll via the existing `src/hooks/useInView.ts` (see below), not a new observer.
- `src/pages/UpcomingEvents/UpcomingEvents.tsx` + `.css` — same search-box-over-a-list shape as Past Events, but the year `<select>` is replaced with a `.calendar-view-button` (`target="_blank"`, linking to the club's real Google Calendar — an `/embed?src=...` URL, meant for an `<iframe>`, but it renders fine as a standalone page too, so it works as a plain link here with no iframe needed) since there's no year dimension to filter upcoming events by. A `.mobile-calendar-view-button` icon-only copy (portaled to `document.body`, next to the mobile hamburger) carries the identical href — both must be updated together if the calendar URL ever changes, there's no shared constant. Placeholder events are sorted soonest-first by a real ISO `date` string (`useMemo` + `.localeCompare`, not just the order they're declared in the array — same "store a real sortable value" reasoning as Past Events' numeric year), rendered via `src/components/UpcomingEventCard/UpcomingEventCard.tsx`.
- `src/components/UpcomingEventCard/UpcomingEventCard.tsx` + `.css` — one upcoming event, deliberately mirrored from `EventCard`: a single graphic placeholder (`{ alt, src? }`, same `photo.src ? <img> : <span>` pattern as `FolderPreview`'s photo slots) on the **left** this time, and a body on the **right** built for a call to action rather than browsing — name, a date/time/location meta line (`src/components/UpcomingEventCard/formatEventDate.ts` formats the stored ISO date for display), description, then two very differently-weighted actions: a filled gradient `.rsvp-button` (same gradient as the site's primary "Become A Member" CTA, so it reads as the button that matters) and a plain underlined `.upcoming-member-link` "Become a member" text link — deliberately not styled as a button, so it never competes with RSVP for attention. Reuses the same `.folder`-style card shell (asymmetric corners, gradient background, cycling colored tab) as `EventCard`.
- Both `formatAcademicYear.ts` and `formatEventDate.ts` live as their own module next to the card component that uses them, rather than being exported from the card's own `.tsx` file — a component file exporting anything else trips `react-refresh/only-export-components`.
- `.merch` itself has **no top padding** (`padding: 0 22px clamp(48px, 6vw, 80px)`), unlike a typical section — `.merch-hero` is always its first child and is a colored full-bleed block, so any padding here just showed as a plain-background gap before the color started, reading as a visible seam right under the header. The only gap now is `.site-header`'s own `margin-bottom: 18px`, the same small gap every page already has.
- `src/pages/Merch/Merch.tsx` + `.css` — a hero (`.merch-hero-copy` eyebrow+`<h1>`+lede, then `MerchCarousel`, then a `.merch-section-nav` of plain `#fragment` links to the sections below, same native-smooth-scroll approach as `#folder-showcase`/`ScrollCue`, no JS scroll handler) sized to fill the initial viewport the same way the homepage's `.hero-section` does — `min-height: calc(100svh - 130px)` on `.merch-hero`'s flex column, reusing that exact same header-height offset for consistency. `.merch-hero`'s `gap` (`clamp(18px, 2.2vw, 26px)`) and `MerchCarousel`'s desktop item size (`clamp(280px, min(30vw, 50vh), 520px)`) both count twice toward how far down `.merch-section-nav` sits. The carousel size was originally kept conservative specifically to keep the nav above the fold on common desktop viewport heights — since then, deliberately enlarged past that constraint per an explicit request to push the nav further down the page instead (verified at 1440x900: the nav now sits right at/just past the fold rather than comfortably above it, which is the intended tradeoff now, not a regression). Unlike `.hero-section` (which drops to `min-height: auto` under `max-width: 980px`), the merch hero deliberately keeps filling the viewport on mobile too — explicitly requested, since the carousel is the point of the page's opening screen, so there's no "awkward empty space" argument for shrinking it there the way there is on the homepage. Content is `justify-content: flex-start` rather than centered: the copy block sits near the top, and `MerchCarousel` (naturally sized, not `flex: 1` — see its own CSS for why that was tried and reverted) plus `.merch-hero`'s own `gap` puts a normal, consistent gap between the carousel and the nav rather than the huge invisible one flex-growing the carousel produced. `.merch-hero-copy` mirrors `Hero.tsx`'s `.hero-copy` shape (a small-caps `.merch-hero-eyebrow` kicker with a short gradient line before it, an `<h1>`, a `.merch-hero-lede` subtitle) but reimplemented under its own classes rather than shared, and — unlike `.hero-copy` — with no card/border/background around the group at all; `.merch-hero` itself carries a much subtler two-radial-gradient color wash (low-opacity pink/blue tints) for a bit of depth instead — each gradient has 4 intermediate opacity stops stepping gradually down to `transparent` at 85% (a single middle stop still read as a visible ring; several small steps spread that far out means the glow disappears well before its own edge, with no hard line anywhere), centered around `20%/38%` and `80%/34%` — well down from the box's own top edge (was `18%/15%`/`82%/12%`), since a center that close to the top still left the color fairly saturated exactly where the box meets the header above it, so the box's top edge itself (not the gradient's own falloff) read as a hard line. An outline/card treatment mirroring `.hero-copy`/`.mascot-frame`'s actual border+background+shadow was tried earlier and explicitly reverted — the color wash was the replacement once the hero started feeling too flat. `.merch-hero` is also full-bleed (`width: 100vw` + negative `calc(50% - 50vw)` margins, the same trick `Footer.css` uses, safe for the same reason: `.site-shell` already has `overflow-x: hidden`) with *no* horizontal padding of its own, so the color wash and `MerchCarousel` (a `width: 100%` direct child) span the entire browser window on every screen size rather than stopping at `.merch`'s 1180px content column. `.merch-hero-copy` and `.merch-section-nav` each carry their own `padding-inline: 22px` instead, so the text still clears the screen edges while the carousel doesn't. On desktop the title is sized/tracked to stay on one line (`white-space: nowrap` + a viewport-width-heavy `font-size` clamp — verified no horizontal overflow at 1280px); on mobile it's allowed to wrap (`white-space: normal`) at an even bigger font-size instead of shrinking to fit one line — verified no horizontal overflow at 360px/375px either. `.merch-hero`'s `padding-bottom` is bigger than a typical section's (`clamp(48px, 7vw, 88px)`) so the nav has real breathing room from the hero's own bottom edge. `.merch-section-nav` links are underlined by default (not just on hover, same recipe as `UpcomingEventCard`'s `.upcoming-member-link`) so they read as clickable at a glance. Then a Clothing section, an Accessories section, and a "Like What You See?" purchasing section, each `id`-anchored (`#clothing`/`#accessories`/`#purchasing`) to match the nav. Clothing/Accessories each have a `.merch-section-title-row` (`<h2>` + a sort `<select>`, same `.year-filter`-style pill as Past Events') above their `.merch-grid` (3 columns desktop, 1 on mobile) of `src/components/MerchProductCard/MerchProductCard.tsx`. Each section's sort is independent local state (`clothingSort`/`accessoriesSort`, both `MerchSort` — `'newest' | 'oldest' | 'price-low' | 'price-high'`, defaulting to `'newest'`), applied via a shared `sortMerchItems` helper over a `useMemo`'d copy of that section's array (never mutates the source `clothingItems`/`accessoryItems`). Price sorting re-derives a number from the display string (`parsePrice`, strips everything but digits/`.`) rather than comparing the `"$45"` text directly. A second, independent "Group by Type" filter (`clothingType`/`accessoriesType`, defaulting to the `ALL_TYPES` sentinel — lowercase `'all'`, so it can't collide with a real capitalized `type` value) sits next to the sort dropdown in a `.merch-section-filters` wrapper (needed so `.merch-section-title-row`'s `justify-content: space-between` still only sees two flex children — `<h2>` and this group — instead of spacing three items evenly apart) and narrows the array by `MerchProductCardProps`'s `type` field (applied via `filterMerchItemsByType` *before* `sortMerchItems`, both inside the same `useMemo`) before sorting. `type` is a per-product free-form string, hidden like `year` — never rendered on the card, it exists purely for this filter — and each section's dropdown options (`clothingTypes`/`accessoryTypes`, via `getMerchTypes`) are derived from that section's own array rather than hardcoded, so adding or removing a product automatically updates the available filter options with nothing else to keep in sync. The purchasing section is two `.merch-purchase-option` cards side by side (stacking on mobile): Option 1 pairs explanatory text with a `.merch-order-button` (same gradient as the site's primary "Become A Member" CTA, `href="#"` placeholder until the club has a real external order form) — Option 2 is just informational text, no button, since buying in person needs no link. Product names/descriptions/prices are still explicit placeholder copy (until the club sets real ones), but the photos themselves are the club's real product shots (`src/assets/merch/*.png`, e.g. `zipup-front.png`/`zipup-back.png`, `robbieHoodie-front.png`/`-back.png`, `boboRobbie.png`, `robbieTote.png`) — one card per distinct product, and any product photographed from both sides (a `-front`/`-back` filename pair) supplies both as that card's `images` array rather than getting split into two cards or losing the back view. The 9 individual sticker designs (6 Robbie-expression ones — `bobo`/`love`/`nerd`/`confused`/`shy`/`cryRobbie.png` — plus `cognitivesisyphusSticker.png`, `cogsportalSticker.jpg`, and `robbiexwugSticker.jpg`, added afterward as more real designs turned up) replaced a single earlier "COGS Sticker Pack" placeholder card that had no real per-design photos to show — now each design gets its own card (`type: 'Sticker'`) instead of being lumped into one generic "pack" tile. The original 3 generic placeholder images (`MerchHoodies.png`/`MerchKeychain.png`/`MerchStickers.png`) are no longer used in the product grids, only still in `carouselImages` for the hero's `MerchCarousel` strip (which wasn't part of this photo update) and as the one remaining stand-in for "Robbie Enamel Pin" (`merchKeychain` — there's no real pin photo yet, so it still reuses the keychain's stock photo, same as before).
- `src/components/MerchCarousel/MerchCarousel.tsx` + `.css` — the hero's photo strip, modeled on ubcuxhub.ca's "people behind the process" marquee rather than `EventCard`'s click-through carousel: no arrows, no dots, purely automatic. `.merch-carousel` deliberately is **not** `flex: 1` — that was tried (to grow the container to fill the hero's leftover height) but `.merch-carousel-item`'s own size stays capped regardless (`width: clamp(..., 46vh, ...)`), so the growing container just left a big invisible gap between the visibly-capped-size images and the section-nav below. It's sized by its own content instead, with `.merch-hero`'s own `gap` providing normal, consistent spacing to the nav. `overflow: hidden` and an edge `mask-image`/`-webkit-mask-image` fade the strip out at both edges into `.merch-hero`'s color wash instead of clipping hard. `.merch-carousel-item`'s width clamp uses `min(vw, vh)` — not just `vw` — on both desktop (`clamp(280px, min(30vw, 50vh), 520px)`) and its `max-width: 980px` mobile override (`clamp(260px, min(72vw, 44vh), 420px)`), so the photos grow into extra vertical room instead of staying a fixed small size regardless of screen height. The mobile clamp in particular is deliberately bigger relative to its desktop counterpart (72vw vs 30vw) — on mobile the opposite problem from desktop showed up: a small carousel left a lot of *unused* vertical room in the hero, and the nav sat higher than it needed to. Both sizes were later enlarged again past their original values, per an explicit request to make the nav sit lower on the page. The image list is rendered twice back to back in one flex `.merch-carousel-track`; a `requestAnimationFrame` loop (same technique as `Cursor.tsx`'s continuous motion — a plain CSS `@keyframes` version of this was tried first and turned out to silently stall in some browser contexts) writes `translateX` on the track directly each frame, wrapping the offset back by exactly half the track's `scrollWidth` once it passes that point — since the second half is an identical copy of the first, the wrap is invisible and the strip appears to scroll forever. Two speeds, both applied every frame off a single `isHovered` ref flag (not a re-render): the full `speed` (90px/s) normally, dropping to a slower but still-nonzero `hoverSpeed` (22px/s) on `:hover`/`:focus` — deliberately never a full stop. Deliberately does **not** stop for `prefers-reduced-motion` like the rest of the site's automatic motion does — explicitly requested to always keep moving. The whole track is `aria-hidden` (and each image's `alt` is emptied) since it's a decorative repeat of photos that already have real alt text on the product cards below. Each image slot still follows `FolderPreview.photo-slot`'s placeholder pattern (`{ alt, src? }`, dashed box until `src` is set, transparent/borderless via `:has(img)`).
- `src/components/MerchProductCard/MerchProductCard.tsx` + `.css` — one product tile: an `images: MerchProductImage[]` array on top (same placeholder-until-`src`-is-set / `:has(img)` pattern as `UpcomingEventCard`'s graphic for each photo), name/description/price below, plus a `year: number` in `MerchProductCardProps` that's never rendered — it exists purely so `Merch.tsx`'s sort dropdown can order oldest/newest correctly, same "store a real sortable value, not a display string" reasoning as Past Events' numeric year. A single-photo product renders exactly like a plain static image, no controls — only `images.length > 1` (every Clothing item, each with a real `-front`/`-back` photo pair) adds `.merch-product-carousel-arrow` prev/next buttons and `.merch-product-carousel-dot` indicators, the identical hand-rolled carousel recipe `PastEventCard`'s `EventCard` uses (`useState` index, wraparound prev/next, clickable dots) with `merch-product-` prefixed classnames instead of shared ones. `.merch-product-image img`'s default `object-fit` is `contain` — right for Accessories, whose photos (flat sticker illustrations, a single centered keychain/tote shot) look wrong cropped — but `#clothing .merch-product-image img` overrides it to `cover`: Clothing's real photos have very mixed native aspect ratios (the zip-up hoodie's shots are tall, ~739x964, versus the crewneck's wide ~597x448), and `contain` let each one keep its own size within the square frame, so a tall photo's garment rendered noticeably smaller (letterboxed) than one in a near-square photo; `cover` fills the square edge-to-edge for every Clothing photo instead, cropping whichever axis runs long, so every card's garment reads as roughly the same size. Scoped to `#clothing` specifically (not the shared default) since Accessories doesn't have — and shouldn't get — this treatment. `cover` crops evenly top-and-bottom by default for a portrait photo like the zip-up hoodie's, which cut into the hood near the top of frame — `MerchProductImage` has an optional `objectPosition` (applied as an inline `style` on the `<img>`, since it's a per-photo override rather than a class-level default) for exactly this, and the zip-up's two photos in `Merch.tsx` set it to `'top'` so the crop comes off the hem at the bottom instead. Both the image frame and the dots row live inside a `.merch-product-carousel` wrapper (a plain flex column with no styling of its own — it adds no extra gap when the dots row doesn't render, so a single-photo card is pixel-identical to before carousel support existed). Reuses `EventCard`/`UpcomingEventCard`'s card shell (asymmetric corners, gradient background) but swaps their colored folder *tab* for a `.merch-product-clip` — an inline paperclip SVG (the standard Feather/Lucide paperclip glyph, which is drawn along a 45deg diagonal by default) rotated `-45deg` to stand it upright. It's a sibling of `.merch-product-carousel` (a direct child of the card) and positioned with a `top` negative enough to clear the *card's* own padding and border, not just the image's — so the loop end pokes out above the whole card rectangle sitting behind the photo, not just above the photo inset inside it. Tinted via the same cycling `--merch-accent` variable; reads as a clipped photo/file rather than a folder, matching a product catalog's feel over the events pages' "browsing a folder" feel.
- `src/pages/About/About.tsx` + `.css` — built from a hand-drawn layout sketch, same process as Merch. A hero (a full-width, centered `.about-hero-title` — `<h1>Meet the CSS</h1>` — on its own line, then an `.about-hero-content` row below it pairing an italic quoted `.about-hero-mission` placeholder statement in `.about-hero-copy` on the left with a static framed placeholder graphic on the right, then an `.about-section-nav` of plain `#fragment` links below — same recipe as Merch's `.merch-section-nav`, no JS scroll handler) sized to fill the initial viewport the same way Merch's hero does, including staying full-height on mobile (Merch's explicit choice, not the homepage hero's "shrink on mobile" default — this page was asked to match Merch specifically). The title used to sit inside `.about-hero-copy` alongside the mission text (both in the left column, image to the right) — moved out to its own full-width line above that row instead, per explicit layout feedback. `.about-hero-mission` is sized as a big pull-quote (`clamp(1.9rem, 3.2vw, 2.8rem)`, a narrow `max-width: 21rem` so it wraps to several lines) rather than regular body copy — at normal paragraph size it looked small and lost next to the full-height photo occupying the same row, so it's scaled up close to heading size (and narrowed, to force more line-wraps) specifically to visually balance against the photo's footprint, even though the two will never match exactly (a paragraph height is content-driven, not fixed). Unlike Merch, this hero has no full-bleed color-wash background, so `.about` uses the same non-zero top padding as every other page (Upcoming/Past Events) rather than Merch's zeroed-out one — there's no seam to work around here. The right-hand hero graphic (`.about-hero-image`) deliberately reuses `Hero.css`'s `.mascot-frame` visual language (two-tone radial gradient wash, faint grid overlay masked to a center vignette, border + shadow) rather than the site's usual dashed-box photo placeholder — it's a single static framed graphic like the mascot, not a small tile in a grid/strip, so it earns the more polished treatment. Then an "Our Team" section, "The COGS Lounge" section, and a "Contact Us!" section, `id`-anchored (`#team`/`#thelounge`/`#contact`) to match both the hero nav and the pre-existing `Header.tsx`/`Footer.tsx` "About" dropdown items, which already pointed at these exact fragment ids as forward-looking placeholders before this page existed (now pointed at `/about#team` etc. instead of a bare fragment, same swap Merch's own links got when it was built). The `<nav>` is wrapped in its own `.about-hero-nav-spacer` (`flex: 1; display: flex; flex-direction: column; justify-content: center;`) rather than being a plain sibling of the title/content in `.about-hero`'s flex column — that spacer grows to consume exactly whatever vertical space is left in `.about-hero` after the title and mission/photo row (i.e. everything down to the hero's own bottom edge, which is the bottom of the initial viewport, since `.about-hero` fills it) and centers the nav inside that leftover space. This is an *exact* centering technique, not a clamp()-based approximation — flex: 1 always consumes exactly the real leftover space whatever it is, so the nav sits precisely centered between the mission statement and the bottom of the screen at any window size/ratio (verified exactly equal gaps above/below the nav at 1440×900, 1024×768, 1440×1300 — a very tall window — and 375×812/768×1024 on mobile). This replaced an earlier attempt that tried to balance the two gaps using matching clamp() coefficients on unrelated rules on either side of the `.about-hero`/`.about-section` boundary — that only worked at specific viewport sizes rather than universally, which is exactly why it was replaced. `.about-hero`'s own `gap` (title-to-content, and content-to-spacer) and its `padding-bottom` use the *identical* `clamp(24px, 4vw, 48px)` on purpose: since the spacer only centers the nav within itself, the nav's total space-above (that gap + half the spacer's leftover height) only exactly equals its space-below (padding-bottom + the other half) if those two clamp()s are identical all the way down to their floor — a merely similar clamp (e.g. matching preferred/max but not the floor) still drifts apart once the viewport is narrow enough to hit the floor.

If more internal routes get added and that reload starts being noticeable, that's the point to introduce `Link` there.
- Each component lives in its own folder under `src/components/<Name>/` with its markup and stylesheet together (`<Name>.tsx` + `<Name>.css`, imported by the component itself). New page sections should follow the same pattern: a new `src/components/<Section>/` folder composed into `App.tsx`, using the existing kebab-case BEM-ish class naming style (`hero-stage`, `hero-copy`, `mascot-frame`, etc). This encapsulation is convention, not enforced — CSS has no real scoping, so a bare tag selector in any component's stylesheet applies everywhere. `Hero.css` had exactly this bug (a bare `h1 { max-width: 12ch; ... }` meant for the homepage's own title, silently constraining every other page's `<h1>` too) until it was caught while giving Merch's title a bigger font — now scoped to `.hero-copy h1`. Double-check for this pattern (an unscoped element selector, not `.some-class`) before assuming a heading/paragraph/etc. on a new page is only affected by that page's own stylesheet.
- `src/components/Header/Header.tsx` owns the `navContent` JSX (nav links + dropdowns + CTA) as one fragment rendered twice: once inside `<nav className="site-nav desktop-only">`, once passed as children to `<MobileNav>`. When editing nav links/dropdowns, edit `navContent` once — both desktop and mobile pick it up.
- `src/components/NavDropdown/NavDropdown.tsx` — reusable hover/click dropdown for nav items (`label` + `items: {label, href}[]` props). On touch devices (`hover: hover` media query fails) it falls back to click-to-toggle instead of CSS hover. Used by both `Header` (desktop) and `MobileNav` (mobile), so `NavDropdown.css` has both a base ruleset and mobile-specific overrides live in `MobileNav.css` (scoped under `.mobile-nav-links`).
- `src/components/MobileNav/MobileNav.tsx` — hamburger button + slide-out panel, rendered via `createPortal` directly into `document.body` (so it isn't affected by header stacking/overflow). Toggles `document.body.style.overflow` while open to lock background scroll.
- `src/components/Cursor/Cursor.tsx` — custom animated cursor (dot + trailing ring) driven by `requestAnimationFrame`, attached via `window` pointer listeners. Self-disables when `matchMedia('(hover: hover) and (pointer: fine)')` is false (touch devices). `Cursor.css` also carries the global `* { cursor: none }` override (and per-element opt-outs) that hides the native cursor everywhere hover is supported — that's a consequence of this feature, not dead code.
- Desktop vs. mobile UI is switched with the `desktop-only` / `mobile-only` CSS classes (defined in `Header.css`), not JS breakpoint checks, except where `matchMedia` is needed to change behavior (cursor, dropdown hover support).
- `Layout.tsx` tracks pointer position on the root `<main>` via `onPointerMove`, writing `--pointer-x` / `--pointer-y` CSS custom properties onto the element for use in CSS (e.g. gradient/spotlight effects in `Layout.css`).
- `src/hooks/useInView.ts` — reusable `IntersectionObserver` hook (`{ ref, isInView }`, reveal-once, threshold configurable) for scroll-triggered entrance animations. `src/components/FolderPreview/FolderPreview.tsx` is the reference usage: it toggles an `is-visible` class from `isInView` and does all the actual animation in CSS transitions. Reuse this hook rather than writing a new observer for the next scroll-reveal section.
- `src/components/FolderPreview/FolderPreview.tsx` + `FolderShowcase.tsx` — the folder-shaped previews below the hero. `FolderShowcase.tsx` owns the data (title/description/href/photos per folder); `FolderPreview.tsx` is the presentational, data-driven single folder. The folder and its 3 photos are absolutely positioned in one shared `.folder-stage` so the photos can start tucked exactly behind the (higher z-index) folder and travel out from underneath it. Each folder's `align: 'left' | 'right'` prop sets a `--dir` CSS custom property that flips both which edge the folder anchors to and the sign of the photos' scatter transform — that's how left/right mirroring is done without duplicating the scatter math. Photos are placeholders (`{ alt }`) until a real image is wanted: add `src` to that photo's data entry in `FolderShowcase.tsx` and it renders an `<img>` instead of the placeholder box, no other changes needed.
- The photo reveal trigger branches on *input capability*, not just viewport width: `(hover: hover) and (pointer: fine)` gets the desktop hover-triggered reveal (plus the pulsing "Hover to explore" `.hover-hint` badge, hidden everywhere else); anything without real hover — phones (`max-width: 980px`) or a desktop-sized touchscreen (`min-width: 981px) and (hover: none)`) — falls back to the same `useInView`-driven scroll reveal, just with different fall directions. `prefers-reduced-motion: reduce` disables all of it by default and then explicitly re-enables the photo transition only for the hover-capable case, since that one is a deliberate user-initiated interaction rather than automatic motion.
- `<section className="folder-showcase" id="folder-showcase">` (in `FolderShowcase.tsx`) is the shared scroll target for "jump to the sections below the hero": both `src/components/ScrollCue/ScrollCue.tsx` (the bouncing bottom-center arrow, shown only while `window.scrollY < 40`, tracked via a plain `scroll` listener rather than `useInView` since it needs continuous position, not a one-shot reveal) and the hero's "Learn what CSS does" link are just plain `<a href="#folder-showcase">`s — the smooth animation is native `scroll-behavior: smooth` on `html` in `index.css`, gated under `@media (prefers-reduced-motion: no-preference)`. No JS scroll handler; a custom `requestAnimationFrame`-eased version was tried and deliberately reverted in favor of the native behavior.
- `src/components/Footer/Footer.tsx` — page footer, deliberately styled *unlike* `.site-header`: a traditional full-bleed bar in `var(--color-dark-plum)` rather than the site's usual centered rounded "card", so it reads as a distinct closing section. `Footer.css` breaks `.site-footer` out of `.site-shell`'s centered padding with the `width: 100vw; margin-left/right: calc(50% - 50vw)` full-bleed trick (safe here specifically because `.site-shell` already has `overflow-x: hidden`), then cancels `.site-shell`'s own bottom padding (`22px` desktop / `14px` mobile — must stay in sync with `Layout.css`) via a matching negative `margin-bottom` + compensating `padding-bottom`, so the dark background reaches the true edges of the page with no gap. Because the background is dark, every descendant color is overridden from the site's default dark-text-on-light to light-on-dark, and the (black-on-transparent) logo image gets `filter: brightness(0) invert(1)` to force it white — don't reuse `.brand-logo`'s styling here, the dark background needs this override. `footerColumns` in `Footer.tsx` is a small sitemap that intentionally mirrors `Header.tsx`'s `NavDropdown` data (same labels/hrefs for Events/Merch/Resources/About) — if the nav dropdowns change, update this array too, there's no shared source of truth between them. ## Styling

- No CSS modules/Tailwind/styled-components — plain CSS, one stylesheet per component, imported by that component (`import './Header.css'` in `Header.tsx`, etc). `Layout.css` only holds the root `site-shell` background/grid-overlay layers. Base/reset styles and site-wide color variables are global, in `src/index.css`.
- Color palette and fonts are defined as CSS custom properties on `:root` in `src/index.css` (`--color-*` variables; fonts are Fraunces for headings, Manrope for body, loaded via Google Fonts `@import`). Reuse these variables rather than hardcoding colors.
- Responsive behavior is handled with plain `@media` queries colocated in each component's own CSS file (main breakpoint at `980px`, plus `hover`/`pointer` and `prefers-reduced-motion` queries) — there is no CSS framework.
- `src/styles/future-sections.css` holds styling for nav items that don't have a built page section yet (Events/Merch/Resources/About — things like `.join-strip`, `.mini-stats`, `.info-grid`, `.stream-list`). **This file is intentionally not imported anywhere.** When you build one of those sections, pull the relevant rules out into that new component's own CSS file rather than importing this file wholesale.

## TypeScript config notes

- `noUnusedLocals` / `noUnusedParameters` / `noFallthroughCasesInSwitch` are enabled — unused variables/params will fail `tsc -b` (and thus `npm run build`).
- `verbatimModuleSyntax` is on — type-only imports must use `import type { ... }`.
